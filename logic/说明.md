# EUPV2026 代码同步说明

本文件记录库存分析和日报/销售分析的当前执行方式、字段口径、计算规则和展示规则。代码是最终执行依据；代码修改后必须同步更新本文件及对应逻辑文件。

## 1. 库存分析执行引擎与回退

- 页面：`modules/stock/available-stock-analysis.html`。
- 默认引擎：JavaScript。SheetJS `0.18.5` 负责读取来源工作簿，ExcelJS `4.4.0` 负责读取 `stock_template.xlsx`、重建输出 sheet 和写出下载文件。
- 回退引擎：Python Legacy。页面选择 `Python Legacy (Fallback)` 后，继续通过 Pyodide 执行 `py/inventory_step1_to_stock.py`。
- 原 Python 文件保留，不删除、不覆盖；两套引擎都使用相同的输入字段、日期范围、SKU 映射、数量计算和零数量 SKU 规则。
- 上传文件优先；未上传且勾选“使用仓库默认文件”时读取 `templates/` 中的默认文件。Inventory、Daily Supply Plan 必填；ODP、Orderfile Base 可选。
- JS 默认适合日常直接生成；如果模板依赖 ExcelJS 未完全保留的自定义名称、外部链接、批注等历史元数据，选择 Python Legacy 回退。

## 2. Product 显示顺序

库存分析中 Product 统一显示为：

`Model | SKU | Connector`

同步位置：

- `modules/stock/stock-analysis-js.js`：从 SKU sheet 读取 Connector，并生成可视化 Product 标签。
- `modules/stock/available-stock-analysis.js`：Product 筛选、图表分产品线、明细表使用同一标签。
- `py/inventory_step1_to_stock.py`：Python 回退路径的 `stock` 和 `To be allocated` 同样输出 Connector。
- `logic/inventory-analysis-logic.md`：记录库存分析的完整取数、计算和呈现规则。

Model、SKU 或 Connector 为空时省略空字段，非空字段仍保持上述顺序。

## 3. 四来源零数量 SKU 过滤

SKU 级别的四个来源和数量口径如下：

| 来源 | 数量口径 |
| --- | --- |
| Inventory | 过滤后的 `Available Stock` 汇总 |
| Daily Supply Plan | 日期范围内 `Available Quantity` 汇总 |
| ODP | 日期范围内 `Quantity` 汇总 |
| To be allocated | `Allocation Status = to be allocated` 的 `Ordered Qty` 汇总 |

规则：

1. 只要一个 SKU 在四个来源中的任一来源存在非零数量，就保留这个 SKU。
2. 四个来源合计都为零的 SKU，不写入生成的 `stock` sheet，也不进入可视化 Product、图表和明细表。
3. 如果只在 To be allocated 有数量，仍创建对应的 SKU/WH 行。
4. `stock` 中某个 SKU 的其他仓库行可以是零，但只要该 SKU 在其他仓库或其他来源有数量，SKU 仍保留；过滤判断是 SKU 级别，不是单行级别。
5. To be allocated 明细中的 `Ordered Qty = 0` 行不写入输出明细。
6. JS 生成可视化数据时再次执行 SKU 级防御过滤；Python 回退读取输出时也执行同样过滤。

## 4. 输出字段和来源

`stock` 基础列顺序固定为：

`WH | Category | Product TCL Report | Family | SKU | Model | Connector | Bin | MOQ | To be allocated | Total QTY | Total MW | MW | Stock`

基础列之后追加起止日期内的每日在途列，格式为 `YYYY.M.D`。

- SKU sheet 的 `Connector`/`CONNECTOR` 值写入 `stock.Connector`、`To be allocated.Connector` 和 Product 标签。
- Inventory、Daily Supply Plan、ODP、Orderfile Base 都通过同一 SKU 映射补齐 Model、Connector、Category、Family、Bin、MOQ。
- 未匹配 SKU 在输出中标记为 `SKU not matched`；该行保留在工作簿中用于追溯，但不进入可视化分析。
- 输出同时生成 `stock`、`To be allocated`、`_Transit Source Map`，并保留模板中的主数据 sheet。

## 5. 计算规则

- Inventory：按 SKU、Category、销售组织汇总 `Available Stock`；排除 Brand=`Other`、China、Business Planning Department 和 Arrival Plan；销售组织映射为 NL、FR、UK、IT、ES。
- Daily Supply Plan：按 SKU、仓库编码、Supply Date 汇总 `Available Quantity`，只保留日期范围内数据，来源标记为 `INV_DSP`。
- ODP：读取 `Total Stcok` 或 `Total Stock`，按 SKU、仓库、ETA 汇总 `Quantity`，只保留有效且在范围内的 ETA，来源标记为 `ODP`。
- 同一 SKU/仓库/日期同时来自 Daily Supply Plan 和 ODP 时数量相加，来源标记为 `MIXED`。
- To be allocated：只取 Allocation Status 为 `to be allocated` 的订单；按 SKU/WH 汇总 Ordered Qty，并保留 CRD 订单明细。
- `Total QTY = Stock + 日期在途数量合计`。
- 仅 PV 产品计算 `MW = Stock × Bin / 1,000,000` 和 `Total MW = Total QTY × Bin / 1,000,000`。
- ESS、HP 产品只保留 Quantity，`MW` 和 `Total MW` 留空。
- To be allocated 不从 `Total QTY` 或 `Total MW` 中扣除。
- 页面总库存概览按 Inventory 在库、Daily Supply Plan 在途、ODP 国内未发货拆分状态并显示数值与占比。PV 使用 Quantity × Bin 换算 MW；ESS、HP 只显示 Quantity。顶部总数为三种状态合计，待分配不计入。

## 6. 展示规则

- 筛选级联顺序：`WH → Category → Product TCL Report → Family → Product`。
- Product 的检索标签为 `Model | SKU | Connector`，筛选、分产品图表和明细表一致。
- 现货曲线从 Stock 开始，按日期累加在途数量；支持 Daily、Weekly、Monthly。
- 支持总计、按 Product 分线、按 WH 分线；来源线区分 Inventory/Daily Supply、ODP、Mixed。
- To be allocated 按 CRD 月份显示图表标记点，并在明细表中计算。
- 明细表按 Product 汇总：`Available Qty = In-stock + In-transit(range) - To be allocated`。

## 7. 日报 / 销售分析

- 页面：`modules/sales/sales-change-analysis.html`、`modules/sales/sales-change-analysis.js`。
- 实际销售读取 `Order details`；Target 读取 `Target`；地区、品牌和月份按页面筛选联动。产品分析中的 Level1/Level2 为同一分析层级的两种可选口径，用户选择其中一个层级及其分类值进行筛选和聚合。
- PV 使用 Revenue EUR、Total MW 和 PV ASP；ESS 使用 Revenue EUR、Sets 和 ESS ASP；PV/ESS 数量不混加。
- 达成率先分别汇总实际和目标，再用汇总值计算；地区卡、总览卡、季度表、产品趋势和排名共用同一口径。
- 完整规则见 `logic/daily-report-analysis-logic.md`。
