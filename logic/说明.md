# EUPV2026 代码同步说明

本文件记录库存分析和日报/销售分析的当前执行方式、字段口径、计算规则和展示规则。代码是最终执行依据；代码修改后必须同步更新本文件及对应逻辑文件。

## 1. 库存分析执行引擎与回退

- 页面：`modules/stock/available-stock-analysis.html`。
- 默认引擎：JavaScript。SheetJS `0.18.5` 负责读取来源工作簿，ExcelJS `4.4.0` 负责读取 `stock_template.xlsx`、重建输出 sheet 和写出下载文件。
- 回退引擎：Python Legacy。页面选择 `Python Legacy (Fallback)` 后，继续通过 Pyodide 执行 `py/inventory_step1_to_stock.py`。
- 原 Python 文件保留，不删除、不覆盖；两套引擎都使用相同的输入字段、日期范围、SKU 映射、数量计算和零数量 SKU 规则。
- 默认在途日期范围为今天至今天后 4 个月，可在页面或命令行参数中调整。
- 导出数量最多保留三位小数，整数不显示尾随小数。
- 上传文件优先；未上传且勾选“使用仓库默认文件”时读取 `templates/` 中的默认文件。Inventory、Daily Supply Plan 必填；ODP、Orderfile Base 可选。
- JS 默认适合日常直接生成；如果模板依赖 ExcelJS 未完全保留的自定义名称、外部链接、批注等历史元数据，选择 Python Legacy 回退。

## 2. Product 显示顺序

库存分析中 Product 统一显示为：

`Model | Connector + Cable Length`

同步位置：

- `modules/stock/stock-analysis-js.js`：按 SKU 优先匹配 SKU sheet，再回退 Legacy，并生成 Family、Size、Connector、Cable Length。
- `modules/stock/available-stock-analysis.js`：Product 筛选、图表分产品线、明细表使用同一标签。
- `py/inventory_step1_to_stock.py`：Python 回退路径同步输出新的库存列和可视化旁路数据。
- `logic/inventory-analysis-logic.md`：记录库存分析的完整取数、计算和呈现规则。

Model、Connector 或 Cable Length 为空时省略空字段，非空字段仍保持上述顺序。

## 3. 活动库存 SKU 过滤

SKU 级别的三个库存来源和数量口径如下：

| 来源 | 数量口径 |
| --- | --- |
| Inventory | 过滤后的 `Available Stock` 汇总 |
| Daily Supply Plan | 日期范围内 `Available Quantity` 汇总 |
| ODP | 日期范围内 `Quantity` 汇总 |

规则：

1. 只要一个 SKU 在三个库存来源中的任一来源存在非零数量，就保留这个 SKU。
2. 三个库存来源都为零的 SKU，不写入库存结果，也不进入可视化 Product、图表和明细表；仅有 To be allocated 数量不再创建库存行。
3. To be allocated 明细中的 `Ordered Qty = 0` 行不写入输出明细。
4. `Remove-list` SKU 使用主数据正常匹配后写入 `Removed SKU` 审计页，并在 `Source` 列标记为 `Removed list`；不写入国家 PV、`ESS+HP Stock` 或品牌 MW Sheet。

## 4. 输出字段和来源

`stock` 基础列顺序固定为：

`WH | Brand | Family | Bin | Model | SKU | Connector | Cable Length | MOQ | Available QTY | MW | Stock`

基础列之后追加起止日期内的每日在途列，格式为 `YYYY.M.D`。

- SKU sheet 的 `Connector` 和 `Cable Length` 写入库存 Sheet、`To be allocated` 和 Product 标签；Legacy 匹配时这两个字段为空。
- Inventory 的 Category 和 Model 直接取来源文件的 Category、Product Model；Daily Supply Plan 同样优先取来源 Category、Product Model，仅在空值时按 SKU 补齐。其余主数据字段以及 ODP、Orderfile Base 产品字段继续通过 SKU 映射补齐。
- 未匹配 SKU 在输出中标记为 `SKU not matched`；`Remove-list` SKU 标记为 `Removed list`。`Removed list` 记录只保留在 `Removed SKU` 审计页，不进入国家 PV、`ESS+HP Stock` 或品牌 MW Sheet；这些四类 Sheet 不显示 `Source` 列。
- 输出 Sheet 按以下顺序生成：五个国家 PV Sheet、`TCL MW`、`SunPower MW`、`ESS+HP Stock`、`PV Stock in CN`、`ESS Stock in CN`、`Allocation Deduction`、`To be allocated`、`Removed SKU`。内部 `MW` 和 `_Transit Source Map` 保留但隐藏；Brand 的 `SUNPOWER` 等写法统一输出为 `SunPower`。
- 国家 PV 按 `Model` 升序；`ESS+HP Stock` 先按 `WH` 升序，再按每个 `WH` 的 `Model` 升序。品牌 MW Sheet 的 `All WH Total` 位于所有数据最上方，各 WH 的 Total 位于对应明细前。

## 5. 计算规则

- Inventory：先排除销售组织为 China 或名称包含 Business Planning Department 的行，再排除 Physical Warehouse Name=`SPTN China FTZ(W73)`；随后排除 Virtual Warehouse Name 以 FRU、HOLD、Market Material、SCRAP、SPEC 开头的行和 Natec Sunenergy B.V. Consignment WH。Brand=`Other` 保留。按销售组织、Virtual Warehouse、Category、SKU、Product Model 汇总当前库存口径，销售组织映射为 NL、FR、UK、IT、ES。
- Inventory 行在 `Virtual Warehouse` 列保留真实仓库名；Daily Supply Plan 和 ODP Arrival Plan 行保留 SPNL、SPTN、SPFR、SPUK、SPIT、SPES 标准代码；国内库存和待分配数据写入该列为空的国家/SKU 汇总行。
- Daily Supply Plan：按国家、标准仓库代码、Category、SKU、Product Model、Supply Date 汇总当前口径数量，只保留日期范围内数据，来源标记为 `INV_DSP`。Category、Product Model 为空时按 SKU 主数据补充。
- ODP：直接读取 `PV SUPPLY DATA` 和 `ESS SUPPLY DATA`。依次排除 SPTN-PVHK New Ark PO# 非空、New Ark PO Type=Offshore、ALLOCATION Planning=Non-EU，以及指定非目标 PORT DESTINATION；能匹配 Arrival Plan 标准仓库的数量按 SKU、国家、标准仓库代码、PV/ESS、Model、ETA 汇总，不能匹配的数量归入 `WH=CN` 的 `Domestic Stock`。
- 完整仓库、产品和日期维度相同的 Daily Supply Plan 与 ODP 数量相加，来源标记为 `MIXED`。
- To be allocated：只取 Allocation Status 为 `to be allocated` 且 Sub Type 不为 Offshore 的订单。CRD 不晚于今天加三个自然月（含逾期）的订单才参与库存扣减；仅处理对应国家 `Inventory Stock + DSP Available` 大于 0 的 SKU。先扣 Stock，再按日期从近到远扣 DSP，最多扣到 0，未扣完数量写入 `Allocation Deduction`。
- 库存 Sheet 只使用 Inventory 和 Daily Supply Plan：`Available QTY = Stock + DSP 日期在途数量合计`。
- `MW` 保留原 `Total MW` 的计算：PV 为 `Available QTY × Bin / 1,000,000`，ESS/HP 留空。
- ODP 继续进入网页、来源追踪和明细，但不写入库存结果 Sheet；`PV Stock in CN` / `ESS Stock in CN` 保留空表。
- 符合条件的 To be allocated 同步扣减国家/ESS Sheet、MW 和品牌 MW 的 Stock、DSP、Available QTY 与 MW；网页仍按原 To be allocated 标记逻辑展示。
- 页面总库存概览按 Inventory 在库、Daily Supply Plan 在途、ODP 国内未发货拆分状态并显示数值与占比。PV 使用 Quantity × Bin 换算 MW；ESS、HP 只显示 Quantity。顶部总数为三种状态合计，待分配不计入。
- 概览支持按 Brand 和 Family（系列）筛选 PV/ESS；无库存的品类指标和图表不显示。

## 6. 展示规则

- 筛选级联顺序：`WH → Category → Family → Size → Product`。
- Product 的检索标签为 `Model | Connector + Cable Length`，筛选、分产品图表和明细表一致。
- 库存曲线从 `Stock + Domestic Stock` 开始，按日期累加在途数量；因此 `WH=CN` 的国内库存同时进入可用库存和总库存图表、明细及汇总统计。支持 Daily、Weekly、Monthly。
- 支持总计、按 Product 分线、按 WH 分线；来源线区分 Inventory/Daily Supply、ODP、Mixed。
- To be allocated 按 CRD 月份显示图表标记点，并在明细表中计算。
- 明细表按 Product 汇总，其中 `In-stock = Stock + Domestic Stock`，`Available Qty = In-stock + In-transit(range) - To be allocated`。

## 7. 日报 / 销售分析

- 页面：`modules/sales/sales-change-analysis.html`、`modules/sales/sales-change-analysis.js`。
- 实际销售读取 `Order details`；Target 读取 `Target`；地区、品牌和月份按页面筛选联动。产品分析中的 Level1/Level2 为同一分析层级的两种可选口径，用户选择其中一个层级及其分类值进行筛选和聚合。
- PV 使用 Revenue EUR、Total MW 和 PV ASP；ESS 使用 Revenue EUR、Sets 和 ESS ASP；PV/ESS 数量不混加。
- 达成率先分别汇总实际和目标，再用汇总值计算；地区卡、总览卡、季度表、产品趋势和排名共用同一口径。
- 完整规则见 `logic/daily-report-analysis-logic.md`。
