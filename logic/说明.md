# EUPV2026 本次代码同步说明

## 1. Product 显示顺序

库存分析中的 Product 信息统一为：

`Model | SKU | Connector`

已同步的位置：

- `modules/stock/available-stock-analysis.html`：Product 筛选框标题和提示文字。
- `modules/stock/available-stock-analysis.js`：生成 `ProductKeyLabel` 的顺序，以及明细表标题。
- `py/inventory_step1_to_stock.py`：生成的 `stock` sheet 继续输出 `Connector` 列；SKU 映射来源为 SKU sheet 的 `Connector`/`CONNECTOR` 列。
- `README.md`、`logic/inventory-analysis-logic.md`、`logic/README.md`：同步说明和字段顺序。

Model、SKU 或 Connector 为空时，Product 标签会自动省略空字段，但剩余字段仍保持上述顺序。

## 2. 零数量 SKU 过滤

四个来源定义如下：

| 来源 | 用于判断的数量 |
| --- | --- |
| Inventory | `Available Stock` 汇总后的 `Stock` |
| Daily Supply Plan | `Available Quantity` 汇总后的日期列在途数量 |
| ODP | `Quantity` 汇总后的日期列在途数量 |
| To be allocated | `Ordered Qty` 汇总后的 `To be allocated` |

规则：

1. Python 生成 `stock` 时，按 SKU 检查四个来源，只要任一来源存在非零数量，就保留该 SKU。
2. 四个来源都没有非零数量的 SKU，不写入 `stock` sheet。
3. 如果只有 To be allocated 有数量，则创建对应的 SKU/WH 行，保证该来源不会被遗漏。
4. `To be allocated` 明细中数量为 0 的订单行不写入输出明细。
5. JavaScript 读取 `stock` 时再次按 SKU 检查 `Stock`、`To be allocated` 和所有日期列；四项都无非零数量的 SKU 不进入 `vizState.rows`，因此不会出现在 Product 筛选、图表或明细表。

## 3. 计算和展示影响

- `Total QTY`、`Total MW`、`MW` 的公式不变，只对保留下来的有效 SKU 行计算。
- Product 筛选、分产品图表、明细表使用同一个 `ProductKeyLabel`，因此显示顺序一致。
- To be allocated 仍按 CRD 日期参与图表标记和明细表 `Available Qty` 计算。
- 本说明与 [库存分析逻辑](./inventory-analysis-logic.md) 共同维护；如来源字段、过滤口径或 Product 标签变化，应同时更新这两个文件以及对应代码。
